## 2. إعدادات التطبيق

### 2.1 إعدادات `app.json` الحالية

التطبيق مُهيأ حالياً بالمعرفات التالية:

```json
{
  "expo": {
    "name": "Mulhim",
    "slug": "mulhim-app-clone",
    "version": "1.0.0",
    "ios": {
      "supportsTablet": false,
      "bundleIdentifier": "app.rork.mulhim-app-clone"
    },
    "android": {
      "adaptiveIcon": {
        "foregroundImage": "./assets/images/adaptive-icon.png",
        "backgroundColor": "#ffffff"
      },
      "package": "app.rork.mulhim_app_clone"
    }
  }
}
```

### 2.2 قائمة التحقق قبل النشر

قبل البناء، تأكد من تحديث ما يلي:

- [ ] **اسم التطبيق**: حدّث `"name"` في `app.json` إلى الاسم النهائي
- [ ] **الإصدار**: حدّث `"version"` إلى رقم الإصدار المناسب (مثل `"1.0.0"`)
- [ ] **معرف الحزمة** (iOS): تأكد أن `bundleIdentifier` فريد ومطابق لحساب Apple Developer
- [ ] **اسم الحزمة** (Android): تأكد أن `package` فريد ومطابق لقائمة Google Play Console
- [ ] **الأيقونات**: تأكد أن `icon.png` (1024x1024) و`adaptive-icon.png` و`favicon.png` جاهزة للإنتاج
- [ ] **شاشة البداية**: تأكد أن `splash-icon.png` جاهزة للإنتاج
- [ ] **رابط سياسة الخصوصية**: مطلوب من كلا المتجرين

### 2.3 إنشاء `eas.json`

أنشئ ملف `eas.json` في جذر المشروع:

```json
{
  "cli": {
    "version": ">= 13.0.0"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal",
      "ios": {
        "simulator": true
      }
    },
    "production": {
      "ios": {
        "autoIncrement": true
      },
      "android": {
        "autoIncrement": true
      }
    }
  },
  "submit": {
    "production": {
      "ios": {
        "appleId": "بريدك@email.com",
        "ascAppId": "معرف_التطبيق_في_App_Store_Connect",
        "appleTeamId": "معرف_فريق_Apple"
      },
      "android": {
        "serviceAccountKeyPath": "./google-service-account.json",
        "track": "production"
      }
    }
  }
}
```

## 3. البناء لـ iOS (App Store)

### 3.1 تهيئة EAS للمشروع

```bash
eas init
```

### 3.2 إعداد بيانات اعتماد iOS

يمكن لـ EAS إدارة بيانات اعتماد iOS تلقائياً:

```bash
eas credentials
```

سيرشدك خلال:
- إنشاء/اختيار شهادة التوزيع (Distribution Certificate)
- إنشاء/اختيار ملف التوفير (Provisioning Profile)
- إعداد مفاتيح الإشعارات (إذا لزم الأمر)

### 3.3 بناء iOS

```bash
# بناء الإنتاج لـ App Store
eas build --platform ios --profile production
```

هذا سيقوم بـ:
1. رفع الكود إلى خوادم بناء Expo
2. بناء ملف `.ipa`
3. توقيعه بشهاداتك
4. توفير رابط تحميل عند الاكتمال

يستغرق البناء عادةً 15-30 دقيقة.

### 3.4 تحميل البناء

بعد الاكتمال، حمّل ملف `.ipa` من:
- رابط المحطة الطرفية المُقدم بعد البناء
- أو من https://expo.dev ← مشروعك ← Builds

## 4. البناء لـ Android (Google Play)

### 4.1 بناء Android

```bash
# بناء الإنتاج لـ Google Play (صيغة .aab)
eas build --platform android --profile production
```

ينتج ملف `.aab` (Android App Bundle)، وهو الصيغة المطلوبة لـ Google Play.

### 4.2 تحميل البناء

حمّل ملف `.aab` من الرابط المُقدم بعد اكتمال البناء.

## 5. التقديم لـ App Store (iOS)

### 5.1 إنشاء التطبيق في App Store Connect

1. اذهب إلى https://appstoreconnect.apple.com
2. اضغط **My Apps** ← **+** ← **New App**
3. املأ:
   - **المنصة**: iOS
   - **الاسم**: Mulhim (ملهم)
   - **اللغة الأساسية**: العربية
   - **Bundle ID**: اختر `app.rork.mulhim-app-clone`
   - **SKU**: `mulhim-app-v1`

### 5.2 معلومات التطبيق

#### المعلومات العامة
- **التصنيف**: الصحة واللياقة (Health & Fitness)
- **التصنيف الثانوي**: نمط الحياة (Lifestyle) - اختياري
- **حقوق المحتوى**: لا يحتوي محتوى طرف ثالث
- **التصنيف العمري**: أكمل الاستبيان (على الأرجح 4+)

#### خصوصية التطبيق
- **رابط سياسة الخصوصية**: مطلوب - قدم رابط سياسة الخصوصية
- **جمع البيانات**: أعلن عن البيانات التي تجمعها:
  - عنوان البريد الإلكتروني (للمصادقة)
  - بيانات الصحة واللياقة (الوزن، سجلات التمارين)
  - بيانات الاستخدام (تفاعلات التطبيق)

### 5.3 تحضير لقطات الشاشة

تحتاج لقطات شاشة للأحجام التالية:

| الجهاز | الحجم | مطلوب |
|--------|-------|-------|
| iPhone 6.7" (15 Pro Max) | 1290 x 2796 | نعم |
| iPhone 6.5" (11 Pro Max) | 1284 x 2778 | نعم |
| iPhone 5.5" (8 Plus) | 1242 x 2208 | اختياري |
| iPad Pro 12.9" | 2048 x 2732 | فقط إذا كنت تدعم iPad |

**لقطات الشاشة الموصى بها** (حد أدنى 3، حد أقصى 10):
1. شاشة خطة التمارين
2. شاشة التغذية/خطة الوجبات
3. شاشة المدرب الذكي
4. شاشة الملف الشخصي/التقدم
5. شاشة إعداد الملف الشخصي

### 5.4 وصف التطبيق

#### الوصف المختصر (العنوان الفرعي)
```
مدربك الرياضي الذكي السعودي
```

#### الوصف الكامل (مثال)
```
ملهم هو مدربك الرياضي الشخصي المدعوم بالذكاء الاصطناعي، 
مصمم خصيصاً لنمط الحياة السعودي. احصل على خطط تمارين شخصية، 
إرشادات غذائية بناءً على الوجبات السعودية التقليدية، وتدريب 
بالذكاء الاصطناعي - كل ذلك بالعربية والإنجليزية.

المميزات:
- خطط تمارين شخصية بناءً على أهدافك ومستواك
- تخطيط غذائي مع وجبات سعودية تقليدية
- مدرب ذكي لاقتراحات التمارين والوجبات
- تتبع التقدم (الوزن، التمارين، السلاسل)
- يعمل في الصالة، المنزل، أو بمعدات بسيطة
- دعم كامل للعربية والإنجليزية

ابدأ رحلتك الرياضية اليوم مع ملهم!
```

### 5.5 التقديم عبر EAS

```bash
# تقديم تلقائي إلى App Store Connect
eas submit --platform ios --latest
```

أو يدوياً:
1. حمّل ملف `.ipa`
2. افتح تطبيق **Transporter** على macOS
3. اسحب ملف `.ipa` إلى Transporter
4. اضغط **Deliver**

### 5.6 TestFlight (مُوصى به أولاً)

قبل الإصدار العام، اختبر عبر TestFlight:
1. في App Store Connect ← TestFlight
2. يظهر البناء تلقائياً بعد الرفع
3. أضف مختبرين داخليين (حتى 25)
4. أو أنشئ مجموعة اختبار خارجية (حتى 10,000)
5. اختبر بشكل شامل على أجهزة حقيقية

### 5.7 التقديم للمراجعة

1. في App Store Connect ← تبويب App Store
2. اختر البناء من TestFlight
3. املأ جميع الحقول المطلوبة
4. اضغط **Submit for Review**
5. المراجعة تستغرق عادةً 24-48 ساعة

## 6. التقديم لـ Google Play (Android)

### 6.1 إنشاء التطبيق في Google Play Console

1. اذهب إلى https://play.google.com/console
2. اضغط **Create app**
3. املأ:
   - **اسم التطبيق**: Mulhim (ملهم)
   - **اللغة الافتراضية**: العربية
   - **نوع التطبيق**: تطبيق
   - **مجاني أم مدفوع**: مجاني

### 6.2 قائمة المتجر

#### تفاصيل التطبيق
- **وصف مختصر** (80 حرف كحد أقصى): مدربك الرياضي الذكي السعودي
- **وصف كامل** (4000 حرف كحد أقصى): نفس وصف iOS أعلاه
- **التصنيف**: الصحة واللياقة

#### الرسوميات

| الأصل | الحجم | مطلوب |
|-------|-------|-------|
| أيقونة التطبيق | 512 x 512 | نعم |
| صورة مميزة | 1024 x 500 | نعم |
| لقطات شاشة الهاتف | حد أدنى 2، أقصى 8 | نعم |
| لقطات شاشة تابلت 7 بوصة | حد أدنى 0 | مُوصى |
| لقطات شاشة تابلت 10 بوصة | حد أدنى 0 | مُوصى |

### 6.3 تصنيف المحتوى

1. اذهب إلى **السياسة** ← **محتوى التطبيق** ← **تصنيف المحتوى**
2. أكمل استبيان IARC
3. النتيجة المحتملة: مُصنف للجميع

### 6.4 أمان البيانات

أعلن عن ممارسات البيانات:
- **البيانات المجمعة**: البريد الإلكتروني، بيانات اللياقة، بيانات الاستخدام
- **البيانات المشاركة**: لا شيء (جميع البيانات للمستخدم فقط)
- **ممارسات الأمان**: البيانات مشفرة أثناء النقل، يمكن للمستخدم طلب الحذف

### 6.5 رفع البناء

#### عبر EAS Submit
```bash
eas submit --platform android --latest
```

#### الرفع اليدوي
1. اذهب إلى **الإنتاج** ← **إنشاء إصدار جديد**
2. ارفع ملف `.aab`
3. أضف ملاحظات الإصدار
4. اضغط **مراجعة الإصدار**

### 6.6 الاختبار الداخلي (مُوصى به أولاً)

1. اذهب إلى **الاختبار** ← **الاختبار الداخلي**
2. أنشئ إصداراً جديداً
3. ارفع ملف `.aab`
4. أضف المختبرين بالبريد الإلكتروني
5. شارك رابط الاشتراك

### 6.7 التقديم للمراجعة

1. اذهب إلى **الإنتاج** ← **إنشاء إصدار جديد**
2. اختر البناء
3. أضف ملاحظات الإصدار
4. اضغط **بدء الإطلاق للإنتاج**
5. المراجعة تستغرق عادةً بضع ساعات إلى 3 أيام

## 7. قائمة التحقق بعد التقديم

### 7.1 بعد الموافقة

- [ ] تحقق من ظهور التطبيق في المتجر
- [ ] حمّل واختبر على جهاز حقيقي
- [ ] تحقق من عمل اتصال Supabase من بناء المتجر
- [ ] تحقق من عمل ميزات المدرب الذكي
- [ ] اختبر تدفق المصادقة (التسجيل، الدخول، الخروج)
- [ ] اختبر تدفق إعداد الملف الشخصي
- [ ] تحقق من إنشاء خطة التمارين
- [ ] تحقق من إنشاء خطة التغذية
- [ ] اختبر تبديل اللغة

### 7.2 المراقبة

- راقب تقارير الأعطال في App Store Connect / Google Play Console
- تحقق من لوحة معلومات Supabase لصحة قاعدة البيانات
- راقب ملاحظات المستخدمين والمراجعات

### 7.3 التحديثات

للتحديثات المستقبلية:
```bash
# زد رقم الإصدار في app.json
# ابنِ إصداراً جديداً
eas build --platform all --profile production

# قدّم
eas submit --platform ios --latest
eas submit --platform android --latest
```

## 8. المشاكل الشائعة وحلولها

### 8.1 فشل بناء iOS

| المشكلة | الحل |
|---------|------|
| انتهاء صلاحية الشهادة | شغّل `eas credentials` لإعادة التوليد |
| تعارض Bundle ID | تأكد أن Bundle ID فريد في بوابة Apple Developer |
| بيان خصوصية مفقود | أضف إدخالات بيان الخصوصية المطلوبة |

### 8.2 فشل بناء Android

| المشكلة | الحل |
|---------|------|
| مشاكل Keystore | EAS يدير Keystores تلقائياً؛ استخدم `eas credentials` |
| تعارض رمز الإصدار | اضبط `autoIncrement: true` في `eas.json` |
| AAB كبير جداً | تحقق من الأصول غير الضرورية في الحزمة |

### 8.3 رفض مراجعة التطبيق

| السبب الشائع | الحل |
|-------------|------|
| سياسة خصوصية مفقودة | أضف رابط سياسة خصوصية في إعدادات التطبيق |
| بيانات وصفية غير مكتملة | املأ جميع الحقول المطلوبة في قائمة المتجر |
| أعطال عند التشغيل | اختبر بشكل شامل على TestFlight/الاختبار الداخلي أولاً |
| مطلوب تسجيل دخول بدون وضع ضيف | ملهم يدعم بالفعل وضع الضيف |
| الحد الأدنى من الوظائف | تأكد من أن جميع الميزات تعمل وموثقة |

### 8.4 متغيرات البيئة

تأكد أن بناء الإنتاج لديه وصول إلى متغيرات البيئة المطلوبة:
- `EXPO_PUBLIC_RORK_DB_ENDPOINT`
- `EXPO_PUBLIC_RORK_DB_NAMESPACE`
- `EXPO_PUBLIC_RORK_DB_TOKEN`

يجب تهيئتها في أسرار بناء EAS:
```bash
eas secret:create --name EXPO_PUBLIC_RORK_DB_ENDPOINT --value "القيمة"
eas secret:create --name EXPO_PUBLIC_RORK_DB_NAMESPACE --value "القيمة"
eas secret:create --name EXPO_PUBLIC_RORK_DB_TOKEN --value "القيمة"
```

## الملخص

عملية النشر تتبع هذه الخطوات الرئيسية:

```
1. إعداد app.json و eas.json
2. البناء باستخدام EAS (eas build)
3. الاختبار عبر TestFlight (iOS) / الاختبار الداخلي (Android)
4. إنشاء قوائم المتجر مع لقطات الشاشة والأوصاف
5. التقديم للمراجعة
6. المراقبة والتحسين
```

كلا المتجرين يراجعان عادةً خلال 24-48 ساعة لـ iOS وبضع ساعات إلى 3 أيام لـ Android. خطط وفقاً لذلك لجدول إطلاقك.
